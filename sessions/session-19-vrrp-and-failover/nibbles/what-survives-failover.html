Session 19 · Nibble · VRRP

What actually survives a failover?

⏱ under 2 minutes · glance & go
VRRP gives you a surviving gateway address — never a surviving session.
Survives the failover? FGCP FGSP VRRP
Gateway IP / MAC ✔ yes ✔ yes ✔ yes
Session state (TCP, NAT) ✔ yes ✔ yes ✘ never
Config synchronization ✔ native ◐ optional ✘ no
Works across vendors ✘ no ✘ no ✔ yes
One empty box tells the whole story: VRRP's session-state column. That gap is architectural, not tunable.
The 9 that lived
Short / stateless flows. A fresh SYN just builds a new session on the new master. Nobody notices.
The 3 that died
Long-lived / stateful / NAT'd flows. They hit the new master out-of-state → dropped → reconnect from scratch.
The wrong-knob trap: a sub-second failover would not have saved those 3 sessions. Faster failover fixes detection time — it does nothing about state loss. The timer is never the fix for dropped sessions.
Need the gateway to survive? → VRRP is fine.
Need the sessions to survive? → VRRP is the wrong tool → use FGCP or FGSP.
