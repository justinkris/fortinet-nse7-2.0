NSE7 EF 7.6 · SESSION 40 · STUDY NIBBLE

Reading diag sys session list

One command. One line. Everything you need to prove NPU offload status.

What this nibble does: Teaches you to read a single session table entry and immediately identify whether the session is NP7-offloaded, CPU-bound, or something in between — and why.

The Command

FortiGate CLI
diagnose sys session list

Lives under diagnose — not get — because it exposes raw internal engine state, not an operational summary. You can filter to one session using a BPF-style filter on the diagnose sys session filter command first.

Anatomy of a Session Entry

session info: proto=6 proto_state=01 duration=142 expire=3599 TCP · established · 142s running
src=10.10.5.47 dst=172.16.1.20 src_port=52341 dst_port=443 trading workstation → market data server HTTPS
state=may_dirty os=6 ws=6 tos=0x00 internal session state flags — noise for offload diagnosis
npu info: flag=0x81/0x81, offload=9/9, ips_offload=0/0 ← THE PROOF LINE
🧠
Mental Model
The npu info line is your offload verdict. Everything else in the session entry is context.

Decoding offload=X/Y

The two numbers represent forward direction / reverse direction. The value is the internal processor code, not a packet count or an index.

ValueMeaningStatus
offload=9/9 Both directions handled by NP7 — full fast-path offload OFFLOADED
offload=0/0 Both directions on CPU — full slow-path (software) NOT OFFLOADED
offload=9/0 Asymmetric — forward on NP7, reverse on CPU. Rare; investigate. ASYMMETRIC
✓ Proof for Priya
offload=9/9
Both directions on NP7. Session is bypassing the CPU. This is your evidence.
✗ Problem to investigate
offload=0/0
no_ofld_reason: ...
Session is on the CPU. The reason field tells you why.

When offload=0/0 — Read the Reason

no_ofld_reasonWhat it meansFix
disabled-by-policy auto-asic-offload set to disable on the firewall policy Re-enable or remove the override
disabled-by-profile A proxy-based UTM profile is attached to the policy Switch to flow-based profiles or split the policy
helper Session requires a session helper (e.g. FTP, SIP) Expected — cannot be changed for these protocols
software-tunnel Traffic using a software tunnel interface (GRE, SSL VPN) Expected — IPsec is the only offloadable tunnel type
Exam trap: disabled-by-policy means the policy has set auto-asic-offload disable explicitly set. disabled-by-profile means a proxy profile killed offload — even if auto-asic-offload is still enabled. These are different root causes requiring different fixes.

One-Glance Reference

Full offloaded session — what you want to see
npu info: flag=0x81/0x81, offload=9/9, ips_offload=0/0, epid=128/166...
  ↑ Both directions = 9 = NP7. No no_ofld_reason line. You're done.
CPU-bound session — investigate further
npu_state=0x000001 no_offload
no_ofld_reason:  disabled-by-policy
  ↑ Find this policy. Check: set auto-asic-offload disable
Proxy profile killing offload
npu_state=0x000001 no_offload
no_ofld_reason:  disabled-by-profile
  ↑ Find this policy. A proxy-based UTM profile is attached.
    All sessions through this policy are CPU-bound. All of them.
⚡
The Key Fact
9 = NP7. 0 = CPU. The slash separates forward from reverse. That's the whole decode.
