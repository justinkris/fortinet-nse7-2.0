SESSION 22 · NIBBLE · STUB vs TOTALLY STUBBY

Banning Needs a Handshake. Sending Fewer Needs None.

Why stub is an area-wide agreement but "totally" is the ABR's decision alone — under two minutes.

Banning an LSA type is a contract — checked in every hello.
Sending fewer LSAs of an allowed type is just… sending fewer.
STUB (bans Type 5)TOTALLY STUBBY (suppresses Type 3 specifics)
What changesAn LSA type is banned from the areaThe quantity of an allowed type drops (one default Type 3 instead of many)
Who configuresEvery router in the area (set type stub)ABR only (set stub-type no-summary)
Enforced byE-bit in hello Options — cleared area-wideNothing — pure origination decision
On mismatchNo adjacency, ever. Invisible neighborNo mismatch possible — receivers just get less
WhyAn unexpected Type 5 in a stub area is a protocol violationFewer LSAs of a known type breaks nothing
⚠ Why the E-bit must be a handshake

If a stub router somehow reached Full with a non-stub neighbor, the first Type 5 to arrive would be an LSA its area isn't supposed to carry. OSPF refuses to tolerate silent disagreement about what belongs in an area — so it refuses the relationship at hello time instead. Clean refusal beats silent corruption.

✓ Why no-summary needs no agreement

Hellos never negotiate quantity. A router receiving one default Type 3 instead of fifty specifics installs it and routes — nothing to reconcile, nothing to break. So the ABR simply stops originating the specifics and originates one default. Its decision alone.

Exam distractor: "configure no-summary on every router in the area." Wrong — internal routers don't even have the Type 3s to suppress; only the ABR originates them into the area. The setting that must match area-wide is type stub (the E-bit); the setting that lives on the ABR alone is no-summary (the "totally").
🧠
MENTAL NOTE
Stub = contract (E-bit, everyone signs, mismatch = no neighbor). Totally = volume knob (ABR turns it down alone). Type needs agreement; quantity doesn't.
