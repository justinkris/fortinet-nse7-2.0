SESSION 22 · BITE · OSPF AUTH, STUB AREAS & SUMMARIZATION

Who Speaks, and How Much They're Told

Five features, two questions. Rapid reactivation — 5 to 10 minutes.

Production OSPF answers two questions a lab never asks: who gets to speak, and how much each router needs to be told.

Authentication and passive interfaces answer the first. Stub areas and summarization answer the second. The exam hides all five inside "why is this not working?" scenarios.

OVERVIEW

The Session in One Paragraph

A rogue Linux laptop on a shared VLAN can become a full OSPF neighbor because default OSPF runs on pure trust — every hello-match field is public. The fixes split by interface role: passive silences interfaces that should never peer (subnet still advertised via Type 1); MD5/HMAC auth guards interfaces that must peer (key never on the wire; per-interface). Meanwhile a one-exit leaf site drowning in Type 3/5 detail needs only its information floor — a default route — delivered by stub (kills Type 5s, E-bit handshake area-wide) or totally stubby (also kills Type 3 specifics, ABR-side alone). When visibility must be kept, area range (ABR) and summary-address (ASBR) compress many prefixes into one stable claim — which stays healthy even when a member dies, so troubleshooting moves inside the area.

PROBLEM & MENTAL MODEL

Two Problems, One Design Session

Problem 1 — who gets to speak

Area ID and timers are broadcast in cleartext every 10 seconds to 224.0.0.5. The subnet is the price of being on the VLAN. MTU isn't even a hello field — it lives in DBD packets (which is why its mismatch symptom is stuck ExStart). Nothing in a standard hello is secret. Matching the fields IS the trust.

Problem 2 — how much a router needs to be told

A router with one exit makes the same decision for every destination: "toward HQ." Its information floor is one default route. Everything above the floor costs LSDB memory plus a partial SPF run every time any prefix changes anywhere — for a router whose next hop can never change.

🧠
PRIMARY MENTAL MODEL
Auth guards interfaces that must speak. Passive silences interfaces that never should. Stub-ness and summarization both trade visibility for stability — and the cost is that troubleshooting must happen closer to the source.
WORKFLOW

The Decision Flow, Compressed

INTERFACE: has legit neighbors? NO → passive (no hellos; Type 1 stub entry still advertised) YES → MD5/HMAC auth (per-interface; mismatch = neighbor never appears) AREA: leaf with one exit? pure leaf, no local ASBR → totally stubby (stub everywhere + no-summary on ABR) leaf that redistributes → NSSA (Type 7 inside → Type 5 at the ABR) needs per-prefix visibility → regular + area range at the ABR EXTERNALS: chunky redistribution at the ASBR? → summary-address

EXAM-CRITICAL

What Fortinet Actually Tests

  • Type 1 vs Type 2 auth — the distractor is plaintext auth "protecting" against a sniffer. One capture defeats it.
  • Auth is per-interface, not a global OSPF setting — and mismatch presents as a neighbor that never appears.
  • Stub on the ABR only = E-bit mismatch = internal routers vanish from the neighbor table. Symptom is missing neighbors, not missing routes.
  • MTU is a DBD field, not a hello field — that's why its mismatch is stuck ExStart, not an invisible neighbor.
  • A stub area can never host an ASBR — that requirement is the entire reason NSSA exists.
  • Area 0 can never be stub of any flavor.
  • A healthy summary proves nothing about a member prefix — it survives on one living component.
  • Passive ≠ removed from OSPF — the subnet is still advertised as a Type 1 stub network entry.
COMMON MISTAKES

The Traps You Personally Hit

MTU in the hello: it isn't. Your own S21 rule was the disproof — if MTU were a hello gate, a mismatch could never strand routers at ExStart.
Auth as a global setting: it's per-interface — that's what allows HMAC on the exposed trunk and nothing on the locked-room link.
"E-bit mismatch forms a half-working adjacency": no hello-gate mismatch ever half-works. Clean refusal beats silent disagreement — no adjacency at all.

ANALOGY

The Gated Community

Analogy

OSPF hardening is a gated community's mailroom policy.

  • Default OSPF — the gate is open and the entry code is printed on the gate itself. Anyone who copies it walks in (rogue neighbor).
  • Plaintext auth — a password shouted across the street. Anyone listening now has it too.
  • MD5/HMAC — a signet ring: you prove you own it by the seal it leaves, but the ring never leaves your hand. Yesterday's seal won't pass today (sequence number).
  • Passive interface — a house that receives mail (subnet advertised) but never answers the door (no hellos, no visitors).
  • Totally stubby — a resident who tells the mailroom "just hand me anything addressed elsewhere — one forwarding slip covers it all" (the default route).
  • area range — the community's street directory lists "Numbers 8–11: this block," and stays printed even if number 9 moves out. The directory is a claim about the block, not a census.

SELF-TEST

Five Questions — Cold, No Notes

A rogue device captures every hello on a VLAN for a week. Which auth type still keeps it out, and what two properties make that true?
Reveal

Type 2 (MD5/HMAC). The key is never transmitted — only a digest of key+packet, which can't be computed without the key — and a non-decreasing sequence number makes captured packets unreplayable.

Stub is configured on the ABR but forgotten on the internal routers. What exact symptom appears, and why?
Reveal

No adjacency forms — the E-bit in the hello Options mismatches, and hello-gate mismatches never half-work. The ABR's neighbor table shows nothing from area-internal routers.

Why does "totally stubby" require no new handshake bit when stub required the E-bit?
Reveal

Stub bans an LSA type — receiving a banned type is a protocol violation, so agreement must be checked up front. Totally stubby just sends fewer Type 3s (one default instead of many) — a quantity change a receiver processes normally. The ABR decides alone.

10.50.9.0/24 is unreachable but its /22 area-range summary is healthy in area 0. Where do you look and why?
Reveal

Inside the source area — the summary survives while one member lives, so it proves nothing about a specific /24. Specifics exist un-summarized only inside the area; summarization happens solely at the border crossing.

An interface is made passive. Complete the sentence: passive hides the ______, not the ______.
Reveal

Willingness to peer, not the network. Hellos stop (no adjacency possible), but the subnet is still originated in the router's Type 1 as a stub network entry.
