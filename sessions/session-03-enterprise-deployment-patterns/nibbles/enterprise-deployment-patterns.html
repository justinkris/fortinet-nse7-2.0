The Five-Role Matrix

One page. One glance. Reconstructs the whole session.

⏱ Under 2 minutes
A firewall's role determines its silicon; its silicon determines its inspection mode; its inspection mode determines its SKU. Never start at the SKU.
🏪
Branch
SD-WAN
  • Defining job Per-app steering across unequal WAN links
  • Silicon SoC4 / SP5 (integrated NP+CP)
  • Inspection Flow
  • Trap Never a VPN hub
🏛️
Datacenter
Throughput
  • Defining job East-west at line rate
  • Silicon Multiple NP7 + discrete CP9
  • Inspection Flow only
  • Trap Proxy = impossible
🚪
Edge
NGFW
  • Defining job Outbound user + TLS decrypt
  • Silicon Balanced NP7 + strong CP9
  • Inspection Flow and proxy
  • Trap Not "inbound protection"
☁️
Cloud VM
vCPU only
  • Defining job Same as physical, no silicon
  • Silicon None — vCPU only
  • Inspection Flow (proxy expensive)
  • Trap BYOL vs PAYG scenario
🚧
ISFW
Internal
  • Defining job East-west policy inside LAN
  • Silicon Sized to internal load
  • Inspection Flow (often transparent)
  • Trap Not just "segmentation"
🧠 The Consultant's Decision Flow
1
Where does it live? Edge, datacenter, branch, cloud, inside the LAN.
2
What's the dominant traffic? Outbound user, east-west server, unequal-WAN steering, inter-zone.
3
What inspection does that need? Flow-only, flow + proxy, or transparent bridging.
4
What silicon does that inspection cost? NP7 for throughput, CP9 for TLS, SoC for integrated efficiency, vCPU for cloud.
5
Which SKU maps to that silicon? Only now does a datasheet enter the picture.
☁️ Cloud-only add-ons
BYOL vs PAYG Rental car vs outright purchase. Long-lived production = BYOL (fixed vCPU entitlement, portable across clouds). Bursty / POC / dev = PAYG (marketplace hourly billing).
SDN Connectors Poll cloud API → populate dynamic address objects from tags, resource groups, VM metadata. Policy survives infrastructure change. Supported for Azure, AWS, GCP, NSX, K8s.
⚠ #1 EXAM TRAP
Edge vs Datacenter confusion. Both are "big HQ boxes" on a diagram. Read for direction (outbound user vs east-west server) and mode (proxy-capable vs flow-only). Edge = CP9-heavy. Datacenter = multi-NP7.
⚠ ISFW JUSTIFICATION
Never reduce to "segmentation". Three reasons: performance isolation, failure isolation, administrative boundary. The third is often decisive — governance rarely accepts a VDOM as a substitute for a physical device.
