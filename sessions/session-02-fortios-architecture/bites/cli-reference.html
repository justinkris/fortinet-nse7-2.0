STUDY BITE · SESSION 02

FortiOS CLI — Quick Reference

Reactivate your mental model in 5–10 minutes

The One-Paragraph Overview

FortiOS organises its CLI into five root commands, each with a fundamentally different purpose. config is the only command that writes to the configuration database. show reads stored configuration but only displays settings that differ from factory defaults — use show full-configuration to see everything. get reads real-time operational state as clean, administrator-friendly summaries. execute performs immediate actions — some irreversible. diagnose exposes raw internal engine state and runs active tests, going far deeper than get. Knowing which root command to reach for — and why — is what lets you navigate the CLI by reasoning rather than memory.

Primary Mental Model
config = write · show = read config · get = read state · execute = do something · diagnose = look inside the engine

The Two Critical Distinctions

show vs show full-configuration: A setting at its default value is invisible to show. Engineers have missed real bugs because they trusted show and the default culprit never appeared. When in doubt, use show full-configuration — or search it with show full-configuration | grep -f <term>.
The execute ping trap: A successful ping FROM FortiGate only tests FortiGate's own traffic (local-out path). User traffic THROUGH FortiGate hits security policies, NAT, and UTM inspection. These are entirely separate paths. Successful ping ≠ users can browse.

The Two Must-Know Diagnose Commands

Packet Sniffer
diagnose sniffer packet <interface> '<BPF filter>' <verbosity> <count>

# Most common usage:
diagnose sniffer packet any 'host 192.168.1.10 and port 80' 4 100

# Verbosity: 1=headers · 2=+direction · 3=+ethernet · 4=+hex · 6=+ASCII
Debug Flow — Always Follow This Sequence
diagnose debug flow filter addr <ip>
diagnose debug flow show console enable
diagnose debug enable
diagnose debug flow trace start 100
# ... reproduce the issue ...
diagnose debug flow trace stop
diagnose debug disable          ← NEVER forget this
Rule #1: Always run diagnose debug disable when finished. Debug output consumes CPU and memory on production firewalls. No exceptions.

Self-Test — Answer Without Looking Up
  1. Which command shows you settings that are still at factory default?
  2. Why does the session table live under diagnose rather than get?
  3. What verbosity level gives you hex payload in the packet sniffer?
  4. You see packets arriving on the sniffer but never leaving. Which tool do you reach for next?
  5. What are the two commands you must always run at the end of a debug flow session?
