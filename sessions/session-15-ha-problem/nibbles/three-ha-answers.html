Study Nibble · under 2 minutes · NSE7 EF 7.6

Three Problems, Three HA Answers

Under two minutes: which protocol, and why the other two are wrong.

Ask two questions: Do the boxes share one identity? Then: Does state need to survive?

Those two questions place every exam scenario. Everything below is just those questions, expanded.

The Decision
💭 THINK FIRST · THE DECISION

Cover the table. Place these from memory: (a) two config-drifted boxes behind a load balancer; (b) matched edge pair, live SLA-bound VPNs; (c) FortiGate replacing a third-party router, no endpoint changes.

  • Which two of the three technologies carry session state — and which is the only one that speaks to other vendors?
  • "The design is active/active, so it must be FGSP." What's wrong with that sentence?
Q1 — MODEL ANSWER
FGCP and FGSP carry session state (both sync IPsec tunnels; FGSP syncs TCP + IPsec by default). VRRP carries identity only — and it's the only open standard, so the only multi-vendor option.
Q2 — MODEL ANSWER
FGCP supports active-active too. Distribution style never distinguishes them — config coupling and shared cluster identity do.

One Glance, Right Protocol

Two questions place every scenario.

Question 1 — one shared identity with synced config? Yes → FGCP: the pair is one logical device; heartbeat, config sync, stateful session sync (including IPsec SAs); failover owned entirely by the cluster; 2–4 devices; A-P or A-A.

No shared identity? Question 2 — must existing sessions survive landing on the other box? Yes → FGSP: independent peers syncing session data only (TCP + IPsec by default), external devices distribute traffic and detect failure; 2–16 peers, FGCP clusters can be peers. No → VRRP: the open-standard identity float — virtual IP + virtual MAC, endpoint ARP caches never change, multi-vendor, moves identity and never state.

MENTAL NOTE
Firefighter test: FGCP = two firefighters sharing one badge number. FGSP = two stations texting each other every active call. VRRP = the emergency phone number itself, reassignable to whichever station answers. Traps: A-A ≠ FGSP; "FGCP can't fail over VPNs" is false (cold spares renegotiate, clusters don't); post-failover CPU spike = expected NP7 resync, not a fault.
