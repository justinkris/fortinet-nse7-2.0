Build the Cluster, Then Kill Box A

Topology, configuration with best practices, and the exact step-by-step sequence after the primary dies.

                         CLIENTS
  • Both boxes identical: same model, firmware, licensing (cluster runs at the LOWEST license level of any member), disk configuration, and operating mode of the management VDOM.
  • Two heartbeat links (port3, port4): directly connected back-to-back for a 2-member cluster, or via a dedicated isolated switch — never through the user network (hellos carry sensitive cluster data and real bandwidth).
  • Traffic interfaces (port1/LAN, wan1/WAN) connect to the same broadcast domains on both boxes, so either box can carry the identical virtual MACs.

Part 2 — Configuration, Line by Line

Box A (preferred primary) — FortiOS CLI
config system ha
    set mode a-p
    set group-id 10
    set group-name "Vaultline-HQ"
    set password <shared-secret>
    set hbdev "port3" 50 "port4" 100
    set session-pickup enable
    set monitor "port1" "wan1"
    set override disable
    set priority 200
end
Box B — identical except priority
config system ha
    set mode a-p
    set group-id 10
    set group-name "Vaultline-HQ"
    set password <shared-secret>
    set hbdev "port3" 50 "port4" 100
    set session-pickup enable
    set monitor "port1" "wan1"
    set override disable
    set priority 100
end
SettingWhy it exists
mode a-pOne member forwards, one stands by with synced state.
group-id 10Double duty: membership credential AND virtual-MAC formula input. Must match within the cluster — and must DIFFER from any other cluster on the same L2 segment.
group-name / passwordMembership credentials only — must match on both members; never feed any formula.
hbdev p3 50 p4 100Two heartbeat interfaces = split-brain insurance. Priorities make it an ORDERED list: port4 (100) is active; port3 is the fallback. Never load-balanced.
session-pickupEnables stateful session sync so inherited connections survive failover (incl. IPsec SAs).
monitorOpt-in link watching — feeds election criterion #1. Without it, a dead WAN circuit is invisible to the cluster.
override disableDefault. No automatic failback; uptime checked before priority. Avoids the double-failover (and double NP7 resync) tax.
priority 200 / 100Marks Box A as preferred — consulted only when interfaces tie and the uptime gap is under 5 minutes. Per-member, never synced.
Best practices checklist: two heartbeat interfaces minimum, isolated from user networks · dedicated session-sync-dev links on busy clusters (session sync riding the heartbeat can starve hellos → false failovers) · unique group-id per cluster per broadcast domain · switch DHCP/PPPoE interfaces to static during initial cluster formation · set override/priority on BOTH members (they never sync) · size each member for its partner's full offloaded workload (S15 resync tax).
Verification after forming: diagnose sys ha dump-by vcluster (roles, uptime, reset_cnt) · diagnose hardware deviceinfo nic port1 (Hwaddr = virtual MAC vs Permanent Hwaddr) · diagnose sniff packet any "ether proto 0x8890" 4 (hellos flowing).

Part 3 — Box A Dies. Step by Step.

Box A loses power at T=0. No warning, no dying gasp. Here is everything that happens, in strict order:

1
Silence on the heartbeat
Hello packets — L2 frames on EtherType 0x8890/0x8891, sent every hb-interval (default 200 ms) — stop arriving on Box B's active heartbeat interface (port4).
2
Declaration of failure — T ≈ +4 s
After hb-lost-threshold consecutive misses (default 20), Box B declares Box A dead. Default math: 20 × 200 ms ≈ 4 seconds. (Tunable: faster detection ↔ more false-positive risk from a busy-but-alive peer.)
3
Self-check — NOT an election race
With no living rival, there is nothing to compare. Box B checks exactly one thing about itself — its own monitored interfaces (port1, wan1) — confirms health, and declares primary unopposed. Its lower priority (100) is irrelevant.
4
Identity adoption
Box B assumes the identical virtual MAC addresses on every equivalent interface (all except heartbeat and reserved management). Client ARP caches need no update — the IP→MAC binding never changed, because the identity was always cluster property.
5
Gratuitous ARP
Box B broadcasts GARPs so every switch relearns which port each virtual MAC now lives behind (MAC→port table refresh). For stubborn high-end switches, link-failed-signal enable would have the former primary drop its links for 1 s — moot here, since Box A's links are already physically down, which flushes the switches anyway.
6
Traffic flows — then the resync tax
Frames reach Box B. Kernel sessions (and IPsec SAs) were already synced via session-pickup — but NP7 hardware entries never cross the sync link, so each inherited session's first packet is CPU-punted to reprogram Box B's fast path. Expect the S15 CPU spike; size for the worst second.
7
Later: Box A returns. Who's primary?
Depends on when. Back within ~5 minutes: uptime gap is indecisive → fallthrough → Box A's priority 200 wins → it preempts (even with override off!). Back after Box B has banked a ≥5-minute lead: Box B keeps primary; priority is never consulted. To fail back deliberately later: diagnose sys ha reset-uptime on Box B.
One-line summary: silence → 4-second verdict → self-check (no race) → same MACs, new box → GARP teaches the switches → traffic flows → silicon relearns. The failover moves the identity; the resync rebuilds the muscle memory.
