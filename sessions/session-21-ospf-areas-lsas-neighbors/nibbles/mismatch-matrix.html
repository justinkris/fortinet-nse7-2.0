SESSION 21 · NIBBLE · OSPF DIAGNOSTICS

The OSPF Mismatch Matrix

Every OSPF misconfiguration leaves a fingerprint. Read the symptom, name the suspect, run one command. This is the reflex the exam tests.

The exam never asks "list the states" — it shows you a router parked somewhere and asks why.

Six fingerprints below. Five park the adjacency at a known state. The sixth is the scariest: it parks nothing, breaks nothing visibly, and quietly routes your traffic down the slow path.

THE MATRIX · SYMPTOM → SUSPECT → PROOF

Read the fingerprint, name the one mismatch

Symptom you observeWhat it meansFirst suspect(s)Command that proves it
NO NEIGHBOR ENTRY AT ALL Hellos are being rejected on arrival — the relationship never begins Hello/dead timer, area ID, subnet/mask, or authentication mismatch. All four are checked inside the hello packet itself. get router info ospf interface on BOTH sides — compare Hello/Dead, Area, network line by line
PARKED AT INIT Their hellos reach you; yours never register with them. One-way street. One-way filtering/ACL, or your hellos not delivered (multicast blocked toward them) diagnose sniffer packet <port> 'proto 89' 4 — are your hellos leaving? Are theirs listing your RID?
PARKED AT 2-WAY Mutual recognition complete; database exchange never begins Case 1 (healthy): both routers are DROTHERs on a multi-router segment — designed behavior. Case 2 (fault): ALL routers priority 0 → election ran perfectly, elected nobody, no DR can ever exist. get router info ospf interface — read Priority and the DR/BDR lines. "No designated router on this network" + Priority 0 everywhere = the fault.
PARKED AT EXSTART / EXCHANGE Master/slave chosen (or being chosen), but DBD packets aren't surviving the trip MTU mismatch (the classic — big-MTU side's DBDs get dropped) · duplicate Router IDs get router info ospf interface + interface MTU on both sides; get router info ospf status to compare Router IDs
FLAPPING — FULL, THEN DOWN, THEN FULL Adjacency forms fine, then dead interval keeps expiring Unstable link, packet loss eating hellos, or asymmetric timers that almost align get router info ospf neighbor repeatedly — watch Dead Time; if it counts to zero instead of resetting near max, hellos are being lost
FULL EVERYWHERE — BUT TRAFFIC TAKES THE SLOW PATH No stuck state. Nothing looks broken. The map is unanimous and wrong. Reference-bandwidth mismatch — one router measures with a 100G ruler, another with the 1G default. Identical LSDBs, mixed rulers, confidently wrong SPF. Also: default ref-bw blindness (1G and 100G both cost 1). get router info ospf interface — read Cost on the links along the path; sanity-check faster link = lower cost, and that auto-cost-ref-bandwidth matches domain-wide
The trap hiding in row 1: a timer mismatch does not park you at 2-Way — it prevents the neighbor entry from ever existing. If you can see a neighbor at ANY state, the hellos already passed the timer/area/subnet/auth checks. That single observation instantly eliminates four suspects. (This was Session 21's own misconception, corrected on the lab bench.)
The one that should scare you (row 6): every other row announces itself. Reference-bandwidth mismatch produces zero symptoms in the neighbor table — Full adjacencies, synchronized LSDBs, and a backbone quietly preferring a 1 Gbps legacy link over the 10 Gbps core. One ruler for the whole kingdom: change auto-cost-ref-bandwidth everywhere or nowhere.
🔎
Mental Note — the 10-second triage
Neighbor missing → hello contents (timers/area/subnet/auth). Neighbor visible but parked → the state names the layer: Init = one-way delivery · 2-Way = DR election (priority!) · ExStart = MTU/RID. Everything Full but paths wrong → costs and the reference ruler. One symptom, one suspect, one command.
